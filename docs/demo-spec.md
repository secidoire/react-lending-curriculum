# 視覚デモと動く例の仕様

ページの中で動くものは2種類ある。

- **視覚デモ**（この文書の(a)〜(d)の4本だけ）：仕組みを見えるようにするための、作り込んだ道具。`explainer/src/demos/` に置く。
- **各回の動く例**：その回の困りごとを読者が自分で踏むための、貸出管理アプリの小さな断片。`explainer/src/examples/<回>/` に置く。

## 各回の動く例の決まり
- 1つの例は、困りごとを1つだけ踏ませる。操作するものは必要最小限にする。
- 例は、コードと実行結果を並べる枠（`<Sandbox>`。`docs/explainer-spec.md`）で見せる。読者がコードを読み、書き換えて試せるようにする。
- 例の入口は `(root: HTMLElement) => void` の形の関数にして export する。枠の定義（どのファイルをどの順でタブに出すか）は、その回の `sandboxes.ts` に書く。
- 同じ枠に入れるファイルは、名前（フォルダを除いた部分）が重ならないようにする。枠の中の import は、名前だけで解決される。
- 1ページに同じ例を複数置けるよう、`id` や `document.querySelector` に頼らず、渡された要素の中だけを操作する。
- 例のコードは、ページに載せて読ませる前提で書く。本題でない部分（枠のHTML、フォームの読み取りなど）は別ファイルに分け、本題のファイルを短く保つ。
- 悪い例は `bad-examples/` に置き、冒頭に `// 教材用の悪い例：<理由>` を書く。読者がコードを開いて読むので、どこが悪いかの答えはコメントに書かない。
- 操作だけで先に気づかせたい例は、コードを閉じた状態（`codeClosed`）で出す。
- テストを書く。良い例は仕様を満たすこと、悪い例は本文が言っているとおりに壊れることを確かめる。次回の困りごとになる挙動も、テストで固定する。
- 演出はしない。色だけで情報を伝えない。外部ネットワークに依存しない。

## 視覚デモ(a)〜(d)

## 共通制約
- 各デモは `explainer/src/demos/<名前>/` に置き、`index.ts` から1つのコンポーネントをexportする。MDXから `<FullVsDiff />` のように使う。
- 状態遷移・差分の判定・ログの整形などのロジックは `logic.ts` に純粋関数として分け、ユニットテストを書く。コンポーネントは表示と操作だけを持つ。
- 本文18px以上、ボタンは最大7つ、画面上の説明は1行。ハイライトは0.6秒のフェードだけにし、枠線とラベルを付ける。
- 1デモのコードは300行以内（logic.tsとテストを除く）。
- 外部ネットワークに依存しない。

## (a) 全描き直し vs 差分更新（0-3）
- **見せること**：全描き直しだと全ノードが置き換わり、フォーカスが消える。差分更新だと変わったノードだけが更新され、フォーカスが残る。
- **画面**：左右2ペイン。それぞれに貸出一覧（5行、各行にメモ入力欄）と、DOM変更カウンタ（追加・削除・属性・テキスト）。
- **操作**：[1件追加] [1行目の状態を切り替える] [自動で切り替える（1.5秒ごと）] [リセット]
  - 当初の案は「自動入力」だったが、「自動で切り替える」に変えた。ボタンを押すとフォーカスがボタンへ移るので、フォーカスが消える様子は、読者が入力欄に打っている間に画面が勝手に変わる形でしか見せられないため。
- **実装**：
  - 左右のペインは、Reactではなく `src/shared-mini-react/` のミニReactで描く。Reactのコンポーネントは `ref` で受け取ったdiv要素を渡すだけにする。
  - ミニReactの起動と後片付けは `useEffect` で行い、クリーンアップでMutationObserverの停止と中身の消去をする。「Reactの外のシステム（ミニReact）と同期する」useEffectの正しい使用例として、コードにコメントを1行書く。
  - MutationObserverで変更ノードを検知してハイライトとカウントを行い、`document.activeElement` を「フォーカス：なし／メモ欄3」のように表示する。
  - 数える属性は、一覧が実際に使っているもの（`aria-label`・`size`・`placeholder`）に絞る。ブラウザの拡張機能などが入力欄に付ける属性を数えないため。
  - ハイライトは `element.animate()` で行う。クラスの付け外しで行うと、それ自体がDOMの変更として数えられてしまう。

## (b) keyの有無とリスト並べ替え（0-3、第1回）
- **見せること**：非制御の入力欄では、key=indexやkeyなしだと、追加・並べ替えのときに入力内容が別の行にずれる。
- **画面**：3列（keyなし／key=index／key=id）。各列に備品名と「借りる理由」欄（defaultValue）を4行並べ、keyの値も表示する。
- **操作**：[先頭に追加] [逆順] [シャッフル] [リセット]。最初に「理由A〜D」を自動で入力しておく。
- **実装**：
  - 「keyなし」の列は、意図的にkeyを省いたことを示すコメントを書き、その行だけlintを無効化する（理由をコメントに書く）。
  - 名前と理由が一致しない行に「ずれ」ラベルを付ける。判定は `logic.ts` の純粋関数にする。
  - 行のコンポーネントは、作られたときの備品名を `useState` で覚えておき、いま表示している備品名と比べる。DOMを読みにいかずに、「同じ位置なら state が引き継がれる」ことそのものを使って判定できる。
  - 入力欄の初期値は「（備品名）を借りる理由」とする（当初の案の「理由A〜D」より、どの備品のものかが一目でわかる）。
  - 「Preserving and Resetting State」の「同じ位置・同じ型ならstateが保持される」と結びつける説明を、MDX側に書く（デモの中には書かない）。

## (c) クロージャによる古い値のキャプチャ（0-4、第5回）
- **見せること**：依存配列を `[]` にした `setInterval(() => setCount(count + 1))` が1で止まる理由を、レンダーごとのスナップショットとして見せる。
- **画面**：左にカウンタと現在のコード、右に「レンダー履歴」のカード（#1 count=0、#2 count=1…）。コールバックが参照しているカードを矢印で示す。
- **操作**：4つのモードを切り替える [バグ版] [関数型更新] [依存配列にcount] [useEffectEvent版]
- **実装**：
  - レンダーごとにrenderIdとcountを履歴に積む。履歴の保持はrefで行い、表示用のstateとは分ける。
  - 「バグ版」は意図的に依存配列を省いているので、その行だけlintを無効化し、理由をコメントに書く。
  - 依存配列モードでは、intervalの作り直しを「×→新規」と表示する。
- **メッセージ**：stale closureはReactのバグではなく、JSのクロージャの性質。3つの対策はそれぞれ意味が違う。

## (d) 更新フェーズのタイムライン（発展A-2）
- **見せること**：1回の操作で「トリガー → レンダー → コミット → useLayoutEffect → 描画 → useEffect」が順に起きること。バッチング、同じ値での省略、再レンダリングされてもDOMが変わらないケースを、ログの並びで見せる。
- **画面**：左に小さな貸出カウンタのアプリ（親と子の2コンポーネント）。右に時系列のログ。各行に「フェーズ名・コンポーネント名・経過ms」を表示し、フェーズごとに枠とラベルを付ける。
- **操作**：[setState 1回] [setState 3回] [関数型更新 3回] [同じ値をset] [pushしてset] [親だけ更新] [ログ消去]
- **実装**：
  - 観察対象のアプリは、解説ページ本体とは別の root に `createRoot` で描画する。この root ではStrict Modeを使わない（二重実行でログが読みにくくなるため）。そのことを画面下に1行で注記する。
  - ログは観察対象アプリのモジュール変数に積み、ログの表示は解説ページ側で `setTimeout` を使って後からまとめて読み取る。表示側のレンダーがログに混ざらないようにするため。
  - レンダーはコンポーネント関数の先頭で、コミットは子要素の ref callback で、描画は `requestAnimationFrame` の中で記録する。useLayoutEffect・useEffectはそれぞれの中で記録する。
  - 「描画」のタイミングはrAFによる近似であることを画面下に注記する。
  - root の作成と破棄は `useEffect` で行い、クリーンアップで `unmount` する。
- **完成確認**：[setState 3回] を押して、レンダーの行が観察対象の各コンポーネントにつき1つずつしか出ないこと。
- **メッセージ**：画面が変わるのは「描画」の行だけ。レンダーの行が出てもDOMが変わるとは限らない。

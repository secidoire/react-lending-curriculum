## 重要度の決め方
- **必須**：Reactのコードを読み書きするのに欠かせない。Aの回の中で、困りごとと一緒に扱う。
- **知っておく**：使う場面は限られるが、出会ったときに「何のためのものか」がわかればよい。Aでは触れる程度にし、Bのリファレンス編で1ページずつ書く。
- **扱わない**：ジュニアが当面使わない、または範囲外。理由を書いて外す。

## 9. Reactの流行りと歴史（R14）

公式ドキュメントは「いまの書き方」だけを説明する。けれども、現場のコードやネットの記事には古い書き方や古い常識が混ざっていて、それが「公式を読んでも納得できない」原因の1つになる。なぜ今の書き方に落ち着いたのかを、経緯として伝える。

**内容は要調査。** 下の候補は出発点で、書く前に一次情報（React公式ブログ、公式ドキュメント、提案者自身の記事）で確かめる。確かめられなかったことは書かない。

| 候補の話題 | 置く場所 | 状態 |
|---|---|---|
| クラスコンポーネントとライフサイクルメソッド → 関数コンポーネントとフック | 第5回の「むかしと今」（「useEffectはライフサイクルの代わり」という誤解の出どころ） | 要調査 |
| ロジックの再利用：mixin → HOC・render props → カスタムフック | 第6回の「むかしと今」 | 要調査 |

| 全体を1本の流れで読める年表と、いまの流行り | Aの最後に作るまとめのページ（第8回のあと） | 要調査 |

決まり：
- 「むかしと今」は、その回の本題（困りごとと仕組み）を読み終えたあとに置く。歴史から入らない。
- 流行りは「いまこう言われている」と「なぜそうなったか」を分けて書く。後者を説明できないものは載せない。
- 古い書き方を「悪い」と書かない。当時の制約の中での解だったことを書く。

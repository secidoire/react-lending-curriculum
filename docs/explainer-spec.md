# 解説ページ仕様（explainer/）

## 目的
- 勉強会で画面に映して説明に使い、終わった後はジュニアが読み返す。この2つを1つのページで兼ねる。
- **サイトだけ読めば全部わかる**ようにする。別冊のハンズオン資料や、手元で動かすコードを前提にしない。困りごとの体験は、ページに埋め込んだ動く例で行う。
- 「ここを押すとここが動く」という、つながりと動きを見せる。静止した図の羅列にしない。
- サイトのコード自体もお手本として読まれる。CLAUDE.mdの規約に従う。

## 機能の範囲
作るもの（これ以外は作らない）：
- ページ一覧（左のナビゲーション）と各回のページ
- 読むモードと発表モードの切り替え
- 下記「共通コンポーネント」の9つ
- デモ(a)〜(d)と、各回の小さな動く例（`docs/demo-spec.md`）

作らないもの：検索、ダークモード切替、ページ遷移アニメーション、コメント・進捗管理、ログイン、外部サービス連携、PDF出力。

## ルーティング（ライブラリを使わない）
- URLは `#/<回>`（例：`#/0-3`、`#/A-1`）。発表モードは `#/0-3?present`。
- `src/router/pages.ts`：`import.meta.glob('../sessions/*.mdx')` でページを列挙し、ファイル名から回のIDと並び順を作る。並び順は 0-1〜0-4 → 01〜08 → A-1, A-2。
- `src/router/useHashRoute.ts`：`useSyncExternalStore` で `hashchange` を購読し、`{ sessionId, present }` を返す。
- ハッシュの解析は純粋関数 `parseHash(hash): Route` に分け、ユニットテストを書く。
- 存在しない回は「ページが見つかりません」とページ一覧を表示する。
- コードには「外部の状態（URL）をReactに取り込む例」であるとコメントを1行書く。発展編で読む題材になる。

## 2つのモード
| | 読むモード（既定） | 発表モード（`?present`） |
|---|---|---|
| 用途 | 後から読み返す | 勉強会で画面に映す |
| `<Steps>` | すべて表示 | 「次へ」ボタン（または→キー）で1つずつ表示 |
| `<Reveal>` | 閉じた状態。クリックで開く | 閉じた状態。クリックで開く |
| 文字サイズ | 標準 | 1.25倍 |
| ナビゲーション | 表示 | 隠す |

- モードはContextで配る（`PresentModeContext`）。ほぼ変わらず広く読まれる値の例として、第6回の題材と対応させる。

## 共通コンポーネント（src/components/）
| 名前 | props | 振る舞い |
|---|---|---|
| `Layout` | children | ナビゲーションと本文の枠。本文の最大幅は760px |
| `Steps` | children | 子を1要素ずつ段階表示する（発表モードのみ） |
| `Reveal` | label?, children | 「答えを見る」ボタンで開閉する。既定は閉。`details` 要素で実装する |
| `Question` | children | 問いかけの枠。「考えてみよう」のラベルを付ける |
| `Misconception` | wrong, children | 「よくある誤解」の枠。誤解（wrong）と正しい理解（children）を並べる |
| `Term` | children | 用語。ページ末尾の用語一覧に自動で集める |
| `DocLink` | href, children | 公式ドキュメントへのリンク。外部リンクの印を付ける |
| `Preview` | label?, children | 動くReactの小さな例を枠で囲み「実行結果」のラベルを付ける |
| `LiveExample` | label?, start | Reactを使わない素のJSの例を、ページの中で動かす。`start(root)` に渡した要素の中に例を組み立てる。「最初からやり直す」ボタンを持つ |

Reactで書いた例は、ふつうのコンポーネントとして `src/examples/<回>/` に置き、MDXから直接使う。

## 各回のページ構成（sessions/*.mdx）
1. 前回の仕様変更チェック（`<Question>`）
2. 困りごと（ページ内の動く例かデモで、実際に踏ませる）
3. 問い（`<Question>`）
4. コードを読む（困りごとの原因になっているコードを、ページに載せて読ませる）
5. 原理の説明（ここで初めて用語を出す）
6. 答え・要点（`<Reveal>`）
7. よくある誤解（`<Misconception>`）
8. 公式ドキュメント（`<DocLink>`。react.dev は日本語版 `ja.react.dev` にリンクする。MDNやweb.devも、日本語版があればそちらにリンクする。`docs/react-dev-map.md` の対応に従い、「この回のあとで読むと腑に落ちるページ」と、その読みどころを1行ずつ書く）
9. 今日の一文
10. 次回の仕様変更予告

1つの回に困りごとが複数あるときは、2〜6を困りごとの数だけくり返してよい。
歴史や流行りに関係する回には、7の前に「むかしと今」の節を置いてよい（`docs/react-dev-map.md` の9。本題を読み終えたあとに置き、歴史から入らない）。
ページの外（別のファイル・コマンド・手元の環境）を見ないと進めない箇所を作らない。DevToolsなど自分のブラウザで確かめられることは、「自分でも確かめるには」として答えの中に添える（読まなくても先へ進めるようにする）。

## MDXの書き方の例
```mdx
import { FullVsDiff } from '../demos/full-vs-diff'

## 全部描き直すと何が起きる？

<FullVsDiff />

<Question>メモ欄に入力中にステータスを切り替えたら、入力はどうなった？</Question>

<Reveal label="答えを見る">
全部作り直したので、入力欄も新しい要素に置き換わり、フォーカスと入力が消えた。
</Reveal>
```

## コードハイライト
- Shikiの rehype プラグインでビルド時にハイライトする（実行時のライブラリは入れない）。
- 行ハイライトはコードブロックのメタ（例：` ```js {2-3} `）で指定する。段階的に見せたいときは、同じコードを行ハイライト違いで `<Steps>` の中に並べる。

## 設定上の注意
- `@mdx-js/rollup` は `enforce: 'pre'` で `@vitejs/plugin-react` より前に置く。
- Vite 8 と plugin-react 6 の組み合わせでのMDX設定は、MDX公式の Vite の手順を確認してから書く。動作しない場合は推測で回避策を足さず、講師に報告する。
- React Compilerは使わない。Strict Modeはルートで有効にする（デモ(d)だけは独立したrootでStrict Modeを外す）。

## テスト
- `parseHash` とページの並び順：ユニットテスト（node）。
- 全ページが例外なく描画できること：Browser Modeのスモークテスト。
- 各回の動く例：良い例は仕様を満たすこと、悪い例は本文が言っているとおりに壊れることを、Browser Modeで確かめる。
- `Reveal` が既定で閉じていること、`Steps` が発表モードで1つずつ出ること：Browser Mode。

## 見た目
- フォントは `"Hiragino Sans", "Noto Sans JP", sans-serif`、コードは等幅。本文16px、行間1.8。
- 色だけで情報を伝えない。枠の種類（問い・誤解・答え）はラベルでも区別する。

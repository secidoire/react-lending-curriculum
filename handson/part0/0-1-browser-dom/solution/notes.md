# 0-1 観察メモ（模範解答）

## 1. 「ページのソースを表示」と Elements パネル
- 違っていたところ：
  - `<table>` の直下に、`index.html` には書いていない `<tbody>` がある（Elements側だけ）。
  - `<p id="count">` に閉じタグ `</p>` が付いている（Elements側だけ）。`<table>` の手前で段落が終わったものとして扱われた。
  - 件数の文字が、ソースでは「（件数を数えています）」、Elementsでは「3件の貸出があります」。
- `index.html` に書いていないものがあったのは Elements パネル。ソース表示は `index.html` と1文字も違わない。

## 2. Elements で書き換えてからリロード
- 画面はその場で変わるが、リロードすると元に戻る。
- `index.html` は変わっていない。書き換えていたのはファイルではなく、ブラウザのメモリの中にあるDOM。
- リロードすると、ブラウザは `index.html` を読み直してDOMを作り直すので、変更は消える。

## 3. Console で textContent を変更
- 実行したコードの例：`document.querySelector('#count').textContent = '5件の貸出があります'`
- 画面と Elements パネルは変わる。「ページのソースを表示」は変わらない。
- 2で手で行ったことと、JavaScriptがしていることは同じ（どちらもDOMを変更している）。

## 4. Paint flashing
- 色を変える：1行目だけが光る。
- 幅を変える：表全体が光る（列の幅が変わると、同じ列のすべてのセルと隣の列の位置が変わる）。
- 理由：色は大きさも位置も変えないので、その行を塗り直すだけで済む。幅は大きさと位置の計算（レイアウト）からやり直しになり、影響を受けた範囲がすべて塗り直される。

## 5. 1000行の追加
実測の例（Chrome、単位はms。数値はPCによって変わる）：

| 方法 | 1回目 | 2回目 | 3回目 |
|---|---|---|---|
| 1行ずつ追加 | 22.6 | 17.8 | 25.5 |
| まとめて追加 | 23.5 | 36.0 | 15.8 |
| 1行ずつ追加し、毎回高さを読む | 880.9 | 762.2 | 799.6 |

- 「1行ずつ」と「まとめて」の差は、ばらつきに埋もれる程度しかない。ブラウザはDOMを変更されてもその場ではレイアウトを計算せず、次に画面を描くときまで後回しにしてまとめて計算するから。
- 「毎回高さを読む」だけが桁違いに遅い。高さは最新のレイアウトがないと答えられないので、読むたびにその場でレイアウトの計算が走る（1000回）。行が増えるほど1回の計算も重くなる。
- `measure.js` が最後にページの高さを読むのは、後回しにされているレイアウトの計算を測定に含めるため。読まないと、「1行ずつ」と「まとめて」はレイアウトの時間が入らず、「毎回読む」だけに入ってしまい、公平に比べられない。

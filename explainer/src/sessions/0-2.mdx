## コードのどこが足りない？

この一覧のコードを読みます。まず、削除ボタンを押したときの処理です。

```ts
deleteButton.addEventListener('click', () => {
  loans.splice(loans.indexOf(loan), 1);
  row.remove();
});
```

`loans` は貸出を入れた配列、`loan` はこの行の貸出、`row` はこの行の要素（`<tr>`）です。配列から1件取り除き、行をDOMから取り除いています。

次に、「追加」を押したときの処理です。ここでの `loan` は、フォームの入力から作った新しい貸出です。

```ts
loans.push(loan);
addRow(loan);
updateSummary();
```

`addRow` は、行を作って表の最後に足す関数です。`updateSummary` は、件数を数え直して表示する関数です。

最後に、「貸出中のみ表示」を切り替えたときの処理です。

```ts
lentOnly.addEventListener('change', () => {
  for (const row of tbody.rows) {
    row.hidden = lentOnly.checked && row.dataset.status !== 'lent';
  }
});
```

`lentOnly` はチェックボックスの要素で、`lentOnly.checked` でチェックの有無を読めます。`tbody` は表の行を入れる要素、`tbody.rows` はいま表にあるすべての行です。
`row.hidden = true` にすると、その行はDOMに残ったまま見えなくなります。`'lent'` は「貸出中」を表す値で、行を作るときに `row.dataset.status` に入れてあります。

<Question>
2つのバグを直すには、それぞれどこに、何を足せばよいでしょうか。
</Question>

<Reveal>

削除の処理には、件数の数え直しが足りません。

```ts {4}
deleteButton.addEventListener('click', () => {
```

```ts {1}
row.hidden = lentOnly.checked && loan.status !== 'lent';
```

## 直す場所を、1か所にできる？

この書き方では、機能を1つ足すたびに、書き忘れてはいけないコードが増えていきます。

<Question>
書き忘れてはいけないコードを増やさずに済む書き方はないでしょうか。
ヒント：操作のたびに「変わったところ」を探すのをやめたら、どう書けるでしょうか。
</Question>

<Reveal>

操作ではデータだけを直し、画面はデータから毎回すべて作り直します。これをB版と呼びます。

```ts {2,3}
deleteButton.addEventListener('click', () => {
  loans = loans.filter((other) => other !== loan);
  render();
});
```

どの操作も、この形です。データを直して、`render()` を呼びます。データは、貸出の配列 `loans` と、絞り込み中かどうかの `lentOnly` の2つです。
B版の `lentOnly` は、チェックボックスの要素ではなく、`true` か `false` の値です。チェックボックスが切り替わったときに、この値を書き換えます。

`render()` は、いまのデータから画面を作り直す関数です。

```ts {4,5}
function render() {
  const visibleLoans = lentOnly ? loans.filter((loan) => loan.status === 'lent') : loans;

  summary.textContent = summaryText(loans);
  tbody.replaceChildren(...visibleLoans.map(createRowFor));
}
```

`summaryText` は「全3件・貸出中1件」の文字を作る関数、`createRowFor` は1件の貸出から行を作る関数です。
`replaceChildren` は、表の行をすべて捨てて、渡した行に入れ替えます。

件数の表示を足すときに書き換えるのは、`render()` の中の1か所だけです。

## 全部作り直すと、何が失われる？

B版にも、困ることがあります。下の2つの一覧で、同じ操作をして比べます。

1. 「リーダブルコード」のメモ欄に、何か文字を入力する。
2. 「プロジェクター」の行の「削除」を押す。

<LiveExample label="動かしてみよう：A版（変わったところだけ直す）" start={startManual} />

<Question>
メモ欄は、それぞれどうなりましたか。
違いが出る理由を、前回の最後の問い（`innerHTML` でまるごと作り直すと何が失われる？）と結びつけて説明してください。
</Question>

<Reveal>

B版では、入力した文字が消えます。A版では残ります。

`render()` は、行をすべて捨てて、新しい行を作り直しています。メモ欄も、見た目が同じだけの新しい入力欄に置き換わりました。
入力中の文字は、データ（`loans`）には入っておらず、DOMの要素だけが持っていました。だから、要素を捨てると一緒に消えます。

これが、前回の最後の問いの答えです。`replaceChildren` での入れ替えも、`innerHTML` での作り直しも、いまある要素を捨てて新しく作る点は同じです。どの入力欄にカーソルがあるか（フォーカス）も、同じようにDOMの要素だけが持っています。次回、入力している最中に画面が作り直される場面で確かめます。

</Reveal>

## 今日の要点

<Question>
「返却期限を過ぎた貸出に『延滞』と表示する」という依頼が来たら、A版とB版で、それぞれ何か所を直すことになるでしょうか。
</Question>

<Reveal label="要点を見る">

| | A版 | B版 |
|---|---|---|
| 書き方 | 操作ごとに、変わったところだけDOMを直す | 操作ではデータだけ直し、画面は全部作り直す |
| 表示を足すときに書き換える場所 | その表示に関わる操作すべて | `render()` の中の1か所 |
| 起きやすいバグ | 操作ごとの直し忘れ（何種類もある） | `render()` の呼び忘れ（1種類だけ） |
| 失うもの | なし | DOMの要素だけが持っていたもの（入力中の文字など） |

行に「延滞」と出すだけなら、どちらの版も、行を作るところの1か所です。
違いが出るのは、その表示が変わるきっかけが増えたときです。たとえば「返却」の操作が入ると、A版では、その操作の中で行の延滞表示も、件数も、絞り込みも直す必要があります。B版では、データを直して `render()` を呼ぶだけです。

どちらの版にも残る問いがあります。延滞は、誰も操作しなくても、時間が経つだけで起きます。そのとき、誰が画面を直すのでしょうか。これは先の回で扱います。

今日の要点は2つです。

- 同じ状態をデータとDOMの2か所に持つと、片方の直し忘れで画面がずれる。
- 一覧のデータを1か所にして画面を全部作り直せば、直し忘れを考えなくて済む。代わりに、DOMの要素だけが持っていたもの（入力中の文字など）が消える。

</Reveal>

## よくある誤解

<Misconception wrong="DOMのAPIが古くて書きにくいから、バグが出る。">

書きやすいAPIに替えても、直し忘れは起きます。問題はAPIではなく、同じ状態がデータとDOMの2か所にあることです。

</Misconception>

<Misconception wrong="気をつけて書けば、直し忘れは防げる。">

今日の2つは、気をつければ防げます。けれども、直す場所は最大で「操作の数 × 表示の数」まで増えていきます。機能が増えるほど、全部を覚えておくことはできなくなります。

</Misconception>

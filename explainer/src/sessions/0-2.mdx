## 直す場所を、1か所にできる？

<Reveal>

操作ではデータだけを直し、画面はデータから毎回すべて作り直します。これをB版と呼びます（`solution/b-render/`）。

```js {2,3}
deleteButton.addEventListener('click', () => {
  loans = loans.filter((other) => other !== loan);
  render();
});
```

どの操作も、この形です。データ（`loans` と、絞り込み中かどうかの `lentOnly`）を直して、`render()` を呼びます。

```js {5,6}
function render() {
  const lentLoans = loans.filter((loan) => loan.status === 'lent');
  const visibleLoans = lentOnly ? lentLoans : loans;

  summary.textContent = `全${loans.length}件・貸出中${lentLoans.length}件`;
  tbody.replaceChildren(...visibleLoans.map(createRow));
}
```

## 全部作り直すと、何が失われる？

B版を開いて、次の順に操作します。

```bash
npx vite handson/part0/0-2-vanilla-list/solution/b-render
```

1. 「リーダブルコード」のメモ欄に、何か文字を入力する。
2. 「プロジェクター」の行の「削除」を押す。

<Question>
メモ欄はどうなりましたか。A版（`solution/a-manual/`、または自分のコード）で同じ操作をすると、どうなりますか。
違いが出る理由を、前回（0-1）の最後の問い（`innerHTML` でまるごと作り直すと何が失われる？）と結びつけて説明してください。
</Question>

<Reveal>

B版では、入力した文字が消えます。A版では残ります。

`render()` は、行をすべて捨てて、新しい行を作り直しています。メモ欄も、見た目が同じだけの新しい入力欄に置き換わりました。
入力中の文字は、データ（`loans`）には入っておらず、DOMの要素だけが持っていました。だから、要素を捨てると一緒に消えます。

これが、前回の最後の問いの答えです。どの入力欄にカーソルがあるか（フォーカス）も、同じようにDOMの要素だけが持っています。次回、入力している最中に画面が作り直される場面で確かめます。

</Reveal>

## 模範解答の要点

<Question>
レビューの問いです。「返却期限を過ぎた貸出に『延滞』と表示する」という依頼が来たら、A版とB版で、それぞれ何か所を直すことになるでしょうか。
</Question>

<Reveal label="模範解答と要点を見る">

模範解答は2つあります。どちらもテストは全件通ります。

| | A版 `solution/a-manual/` | B版 `solution/b-render/` |
|---|---|---|
| 書き方 | 操作ごとに、変わったところだけDOMを直す | 操作ではデータだけ直し、画面は全部作り直す |
| 表示を足すときに書き換える場所 | その表示に関わる操作すべて | `render()` の中の1か所 |
| 起きやすいバグ | 直し忘れで、データと画面がずれる | `render()` を呼び忘れない限り、ずれない |
| 失うもの | なし | DOMの要素だけが持っていたもの（入力中の文字など） |

延滞の表示を足す場合、B版は `render()` が呼ぶ「行を作るところ」の1か所に書けば、どの操作のあとにも反映されます。A版は、行を作るところに加えて、表示を直しているほかの場所もすべて見直すことになります。

どちらの版にも残る問いがあります。延滞は、誰も操作しなくても、時間が経つだけで起きます。そのとき、誰が画面を直すのでしょうか。これは先の回で扱います。

今日の要点は2つです。

- 同じ状態をデータとDOMの2か所に持つと、片方の直し忘れで画面がずれる。
- 一覧のデータを1か所にして画面を全部作り直せば、直し忘れを考えなくて済む。代わりに、DOMの要素だけが持っていたもの（入力中の文字など）が消える。

</Reveal>

## よくある誤解

<Misconception wrong="DOMのAPIが古くて書きにくいから、バグが出る。">

書きやすいAPIに替えても、直し忘れは起きます。問題はAPIではなく、同じ状態がデータとDOMの2か所にあることです。

</Misconception>

<Misconception wrong="気をつけて書けば、直し忘れは防げる。">

今日の2つは、気をつければ防げます。けれども、直す場所は最大で「操作の数 × 表示の数」まで増えていきます。機能が増えるほど、全部を覚えておくことはできなくなります。

</Misconception>

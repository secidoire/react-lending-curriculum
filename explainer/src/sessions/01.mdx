## 同じ表示を、1か所に書くには？

<Question>
「種類の表示」を1か所にだけ書いて、3つの場所から使い回すには、どうすればよいでしょうか。
ふつうのJavaScriptで、同じ処理を何度も使いたいときにすることを思い出してください。
</Question>

<Reveal>

関数にします。Reactでは、画面の一部を返す関数を<Term>コンポーネント</Term>と呼びます。種類の表示を、`CategoryBadge` というコンポーネントにします。

```tsx
type Props = { category: Category };

export function CategoryBadge({ category }: Props) {
  if (category === 'book') {
    return <span className="badge badge-book">本</span>;
  }
  return <span className="badge badge-equipment">備品</span>;
}
```

使う側は、HTMLのタグと同じように書きます。

```tsx
<CategoryBadge category={item.category} />
```

タグに書いた属性（`category={...}`）は、1つのオブジェクトにまとめられて、関数の引数として渡されます。この引数を<Term>props</Term>と呼びます。`{ category }: Props` は、そのオブジェクトから `category` を取り出しています。

コンポーネントの名前は、大文字で始めます。JSXが関数呼び出しに書き換えられるとき、小文字で始まるタグ（`<span>`）は文字列の `'span'` になり、大文字で始まるタグ（`<CategoryBadge>`）は `CategoryBadge` という関数そのものになります。この違いで、HTMLの要素と自分で作ったコンポーネントが区別されます。

`CategoryBadge` の中では、`if` で返すJSXを切り替えています。条件によって表示を変えることを、<Term>条件付きレンダー</Term>と呼びます。JSXの波括弧の中には `if` を書けないので（0-3で見たとおりです）、JSXの外で `if` を使うか、波括弧の中で `条件 ? A : B` を使います。

</Reveal>

<Reveal>

## セルを2つ返したいとき、どう書く？

`StatusCells.tsx` を開いてください。「状態」と「借りている人」の2つのセルを返しています。

```tsx
export function StatusCells({ lentTo }: Props) {
  return (
    <>
      <td>{lentTo !== null ? '貸出中' : '貸出できます'}</td>
      <td>{lentTo !== null ? `${lentTo}さん` : '—'}</td>
    </>
  );
}
```

<Question>
0-3で、「関数が `return` できるJSXは、いちばん外側の要素が1つだけ」という決まりを見ました。
ここで、2つの `<td>` を `<div>` で包まずに `<>…</>` で包んでいるのは、なぜでしょうか。
`<div>` で包んだとすると、できあがるHTMLでは、表の行（`<tr>`）の中身はどうなるでしょうか。
</Question>

<Reveal>

表の行（`<tr>`）の直下に置けるのは、セル（`<td>` や `<th>`）だけです。`<div>` で包むと、`<tr>` の中に `<div>` が入ることになり、表として正しくないHTMLになります。ブラウザがそれをどう表示するかは保証されず、読み上げソフトも表として正しく読めなくなります。

`<>…</>` は<Term>フラグメント</Term>と呼ぶ入れ物です。「外側は1つ」という決まりは満たしますが、DOMには何も残りません。できあがるDOMでは、2つの `<td>` が `<tr>` の直下に並びます。

`LentItems.tsx` でも、`<p>` と `<ul>` を並べて返すために使っています。`LentItems` は、貸出中のものが1件もなければ `null` を返します。コンポーネントが `null` を返すと、その場所には何も表示されません。

</Reveal>

## 1行選ぶと、どのコンポーネントが呼ばれる？

次は、行を1つ選べる一覧です。どの行が選ばれているかを、`SelectableList` が state（`selectedId`）として持っています。
`SelectableList` と `SelectableRow` は、自分が呼ばれるたびに、`console.log` でそのことを知らせます。出力は、実行結果の下の「コンソール」に出ます。

この例には、新しい書き方が2つあります。

- `onSelect={() => setSelectedId(item.id)}`：props には、関数も渡せます。`SelectableRow` は、「選ぶ」が押されたら、受け取った `onSelect` を呼びます。こうして、子のボタンから、親が持っている state を替えられます。
- `{selected && '選択中'}`：`selected` が `true` のときだけ「選択中」と表示します。`false` のときは、何も表示されません。

「プロジェクター」の行の `SelectableRow` は呼ばれましたが、返したJSXを前回のものと見比べても、DOMに書くべき違いがありませんでした。だから、その行のDOMには何も書かれません。
入力したメモは、state ではなく、DOMの入力欄が持っています（0-2・0-3で見たとおりです）。入力欄が同じ要素のままなので、メモが残ります。
DOMに書かれたのは、「リーダブルコード」の行の `class` と、「選択中」の文字だけです。

レンダーは、「いまの state なら、画面はこうなるはず」という計算です。DOMに何を書くかは、前回と見比べた結果で決まり、違いがなければ何も書かれません。

もう1つ、決まりがあります。コンポーネントの関数は、自分のコードから `SelectableRow(...)` のように直接は呼びません。JSXに `<SelectableRow />` と書いておき、呼ぶのはReactに任せます。
Reactは、`useState` で預かった値を、「レンダーツリーのどの位置のコンポーネントのものか」で覚えています。自分で呼んだ関数は、ツリーの中に位置を持たないので、state を正しく覚えてもらえません。この仕組みは、発展編で自分の手で確かめます。

</Reveal>

## 今日の要点

<Question>
レビューの問いです。一覧の表に「置き場所」の列を1つ足すことになったら、部品に分けた版では、どのファイルを直すことになるでしょうか。
</Question>

<Reveal label="答えと要点を見る">

直すのは、データの形を決めている `items.ts`、見出しを持つ `ItemList.tsx`、セルを並べている `ItemRow.tsx` です。`CategoryBadge.tsx`・`StatusCells.tsx`・`LentItems.tsx` は、開く必要がありません。
「どのファイルを開かなくてよいか」がすぐに言えることが、分けた効果です。

- コンポーネントは、props を受け取って、画面の一部（JSX）を返す関数。
- 分ける基準は、変わる理由。一緒に変わるものを、同じ場所に書く。
- データは、props で親から子へ渡る。
- 親が再レンダーされると、子も再レンダーされる。ただし、再レンダーされても、DOMが書き換えられるとは限らない。

</Reveal>

## よくある誤解

<Misconception wrong="再レンダーは、DOMを作り直すことだ。だから、できるだけ避けるべきだ。">

再レンダーは、コンポーネントの関数を呼んで、前回と見比べる計算です。DOMに書かれるのは、違っていたところだけです。ふつうの画面では、この計算は十分に速く、最初から避けようとする必要はありません。遅さが実際に問題になったときの調べ方と直し方は、第7回で扱います。

</Misconception>

<Misconception wrong="コンポーネントは、コードを短くするために分ける。">

分ける基準は、長さではなく、変わる理由です。短くても、別々の理由で変わるものが混ざっていれば、直す場所を探すことになります。長くても、一緒に変わるものだけなら、1つのままでかまいません。

</Misconception>

<Misconception wrong="コンポーネントはただの関数だから、ItemRow(props) のように自分で呼んでもよい。">

自分で呼ぶと、Reactはそれをレンダーツリーの中のコンポーネントとして扱えず、state を正しく覚えられません。`<ItemRow />` と書いて、呼ぶのはReactに任せます。

</Misconception>
